## 1. 产品概述

| 项 | 内容 |
|---|---|
| 产品名 | 团队每日工作台（Team Daily Workbench） |
| 定位 | 面向**团队主管**的本地优先（Local-First）Web / 桌面工作台 |
| 核心价值 | 把 Outlook 邮件、钉钉日志与日程聚合到一处，用 AI 做分类、提炼与生成，配套每日/周报、待办、复盘、日历、项目时间线，并给出每日工作建议 |
| 形态 | 浏览器可访问 + 可打包为桌面 `.exe` / `.dmg`；单机本地优先，数据存本地 SQLite |
| 目标用户 | 同时管理多个项目的团队主管（关注需求评审、设计、开发、测试、上线等跨项目时间线） |

**一句话**：让主管每天打开一个面板，就能看完邮件待办、团队卡点、会议、日志、复盘与项目进度，并由 AI 自动产出日报/周报与今日建议。

---

## 2. 用户角色

- **团队主管（主用户）**：使用全部功能，查看团队日志/负载、授权接入 Outlook 与钉钉、审阅并覆盖 AI 产出、维护日志模板。
- **团队成员（被管理对象）**：通过钉钉日志/日程被拉取数据，其「已提交/未提交」状态在主界面呈现；主管侧可查看与分析，但成员不直接操作本系统。

## 3. 功能需求（按模块）

> 状态图例：✅ 已实现（代码已落地）｜🔌 需配置（框架已实现，填密钥 + OAuth 后用真实数据）｜📝 规划中

### 3.1 概览面板（Overview / 概览2 指挥台）
- **描述**：两个聚合首页。`/` 为经典概览；`/overview2` 为「指挥台」风格的数据仪表盘，一打开即看到当日全局态势。
- **核心功能**：
  - 经典概览：聚合展示当日「待处理邮件、会议、团队卡点、未提交日志、待办数、风险项目」。
  - 指挥台：4 张 KPI 卡（项目健康度 / 邮件负载 / 日志提交率 / 待办完成率）+ 风险雷达 + 会议时间轴 + AI 今日建议 + 待处理邮件流 + 团队信号（阻塞/待审/未提交）。
  - AI 今日工作建议：`GET /api/overview/suggestion`，数据感知 + LLM 生成，带 1 小时缓存，支持 👍/👎 反馈与重新生成；AI 不可用时回退确定性模板建议。
- **实现状态**：✅ 已实现（`OverviewPage.jsx`、`Overview2Page.jsx`、`routers/system.js` 中的 `/overview` 与 `/overview/suggestion`）
- **数据来源**：emails / calendars / dingtalk_reports / todos / projects + project_phases（状态机推导）

### 3.2 邮件处理（Outlook AI 分类）
- **描述**：拉取 Outlook 邮件，AI 分类到「需处理 / 无需处理 / 不确定」三类队列，支持人工修正、一键转待办、AI 生成回复草稿。
- **核心功能**：
  - OAuth 接入：**PKCE 公共客户端（多租户，无 Secret）**，权限 `Mail.Read` + `offline_access`；令牌 **AES-256-GCM 加密**存本地。
  - **两种授权通道**：授权码流（浏览器回跳）+ **设备码流（RFC 8628）**——浏览器打不开 Microsoft 登录页或无法回跳 127.0.0.1 时，在手机等任意设备输入用户码完成授权。
  - AI 分类字段体系：`queue`（action / informational / uncertain）、`actionType`（reply / approval / confirmation / submission / deadline / other）、`priority`（P0/P1/P2）、`confidence`、`summary`、`actionText`、`dueAt` + `dueSource`（explicit / inferred / none）、`priorityReason`。
  - 人工覆盖：修正对话框可改队列/动作类型/动作文本/截止/优先级/原因，写回本地状态并镜像到 `emails` 表（人工修正在下轮同步中保留）。
  - **一键转为待办**：`POST /api/outlook/messages/:id/task`，把 AI 建议的动作与截止日期写入本地 `todos` 表，邮件标记为 `converted`。
  - **AI 回复草稿**：基于邮件正文 + AI 分类建议 + 主管未完成待办上下文起草回复；支持语气 `formal / friendly / action`；本地生成 + 缓存（`email_drafts` 表），不写回 Outlook，可复制到剪贴板；打开对话框时不自动调 AI（避免意外消耗），换语气或点「重新生成」才覆盖。
  - 未配置时注入**合成演示数据**。
- **实现状态**：✅ 已实现框架 / 🔌 真实数据需配置（`server/outlook.mjs`、`outlook-draft.mjs`、`routers/outlook.js`、`EmailsPage.jsx`；`emails` / `email_drafts` 表；`outlook-draft.test.mjs` 单测）
- **接口**：`GET /api/outlook/{status,todos,archive,all,informational,uncertain}`、`POST /api/outlook/{consent,sync,disconnect,oauth/start,oauth/device/start,oauth/device/poll,messages/:id/task,messages/:id/draft}`、`PATCH /api/outlook/messages/:id/correction`、`POST /api/outlook/todos/:id/status`
- **自动同步**：`startScheduler()` 每 **15 分钟**自动同步一次；同步带**自愈重试**——发现「open 且未分类且带 processingError」的遗留邮件时，把 cutoff 回退到最早遗留时间强制重试；单次同步上限 500 封，正文裁剪 12000 字符，AI 只接收裁剪后正文且**不落库原文**。

### 3.3 团队日志（钉钉）
- **描述**：拉取钉钉成员日志，AI 提炼阻塞点与待审核要点，区分已提交/未提交，支持历史日期查看与模板管理。
- **核心功能**：
  - 钉钉 OAuth 接入（企业内部应用 appToken，无需按主管 userid 过滤，可直接读组织内日志）。
  - **日志模板手动维护**：新增 `report_templates` 表（name 唯一必填 + enabled 启停），替代旧的「调钉钉接口查全部模板 + 勾选」方案；同步时按 `enabled=1` 的模板名（`template_name`，注意**不是 template_id**）服务端过滤拉取；跨模板去重 + 安全网（丢弃服务端偶发未过滤的非目标模板）；无启用模板时同步直接跳过。CRUD 接口 `/api/team/report-templates`，前端在团队日志页「日志模板」面板内联管理。
  - 日志内容**结构化**：`content_json` 保留钉钉原始 `contents` 结构 `[{sort, type, key, value}]`，兼容旧扁平字符串格式；前端按 key 分区展示（今日完成/遗留/明日计划等），支持部门筛选。
  - AI 提炼阻塞点（`blockers`）与待审核要点（`needs_review`）；用 user_id / user_name 双键匹配 AI 结果，**雷同或空的小结回退为真实内容的确定性摘要**，AI 不可用时统一兜底。
  - 未提交基线：`getRosterBaseline()` 取「历史真实提交人」，当日未出现在 `dingtalk_reports` 即视为未提交（集中一处，便于将来切换为手动名册/通讯录基线）。
  - 翻页：`topapi/report/list` 单页最多 20 条，`has_more=true` 时用 `next_cursor` 继续拉，避免高流量模板丢数据。
- **实现状态**：✅ 已实现框架 / 🔌 真实数据需配置（`server/dingtalk.mjs`、`routers/team.js`、`TeamLogsPage.jsx`；`dingtalk_members` / `dingtalk_reports` / `report_templates` 表）
- **接口**：`GET /api/team/{members,reports,load,report-templates}`、`POST /api/team/{sync/reports,report-templates}`、`PUT/DELETE /api/team/report-templates/:id`

### 3.4 日历 / 日详情（含钉钉日程）
- **描述**：月视图日历 + 会议组件，点击任意一天聚合当日邮件、待办、会议、日志、复盘与日报。
- **核心功能**：
  - 钉钉日程自动同步：`GET /api/calendar/{meetings,week,month,day/:date}` 前按需拉取（需 `DINGTALK_MANAGER_USER_ID` 圈定主管主日历，staffId→unionId 进程内缓存）；按天做 **30 分钟 TTL 缓存**，失败标记已尝试避免轰炸；手动同步 `POST /api/calendar/sync` 可指定日期范围。
  - 会议展示组件 `MeetingSchedule.jsx`：当前进行/即将开始/已结束识别、线上会议（URL 定位）一键加入、组织者/地点/时长展示。
  - 周/月视图摘要：每天显示会议数、待办数、待处理邮件数。
- **实现状态**：✅ 已实现（`routers/calendar.js`、`CalendarPage.jsx`、`MeetingSchedule.jsx`；`calendars` 表，钉钉来源 id 前缀 `dt_`）
- **接口**：`GET /api/calendar/{meetings,week,month,day/:date}`、`POST /api/calendar/sync`

### 3.5 今日待办（Todos）
- **描述**：手动添加个人任务，支持状态 / 优先级 / 截止日期；也可由邮件「一键转待办」写入。
- **核心功能**：增删改查；状态（inbox/done 等）、优先级（P0/P1/P2）、截止日期、完成时间自动记录。
- **实现状态**：✅ 已实现（`routers/todos.js`、`TodosPage.jsx`、`todos` 表）

### 3.6 今日复盘（Review）
- **描述**：记录「所做事、所学、所错、状态」，形成成长复盘。
- **核心功能**：每日复盘条目 upsert（按 review_date 唯一）。
- **实现状态**：✅ 已实现（`routers/review.js`、`ReviewPage.jsx`、`daily_reviews` 表）

### 3.7 AI 热点（AiHot）
- **描述**：集成公开 AI HOT 接口，多源信源，今日必看 / 可浏览分层。
- **核心功能**：拉取并缓存（15 分钟 TTL）；按 Agent 工作流 / 安全边界 / 模型能力 / 知识工作等关注域打标；信源可信度分级（多源 / 可回查原文 / 仅聚合摘要）。
- **实现状态**：✅ 已实现（`routers/aihot.js`、`AiHotPage.jsx`、`aihot.mjs`、`ai_hot_cache` 表）
- **说明**：使用公开热点接口（`AI_HOT_ORIGIN` 可配，默认 `https://aihot.virxact.com`），非邮件/钉钉类需授权数据源。

### 3.8 项目时间线（Projects / Roadmap）+ 状态机
- **描述**：手动录入项目「需求评审 → 产品设计 → 开发 → 测试 → 上线」阶段，渲染为 roadmap；**状态由状态机自动推导**。
- **核心功能**：
  - 项目 + 阶段 CRUD；项目可设负责人/颜色/备注/进度。
  - **项目状态机**（`server/project-status.mjs`，projects 与 overview 复用）：`normal / at_risk / review / overdue / done` 五态，自动推导规则：
    - 超过最终截止未完成 → **已逾期**（overdue）
    - 进度 ≥ 100% → **待验收**（done）
    - 当前处于「测试 / 上线」阶段 → **审核中**（review）
    - 7 天内有关键节点截止但进度 < 70% → **有风险**（at_risk）
    - 其余 → 正常
  - 进度：存储值优先；未设置时按阶段时间跨度自动估算（0~100）。
  - 概览页「风险雷达」自动预警 at_risk / overdue 项目。
- **实现状态**：✅ 已实现（`routers/projects.js`、`ProjectsPage.jsx`、`project-status.mjs`；`projects` / `project_phases` 表，项目删除级联删阶段）
- **说明**：阶段为手动录入，非自动从研发系统同步。

### 3.9 团队负载（TeamLoad）
- **描述**：按成员聚合当日提交、阻塞、待审，算出**负载指数**并标出过载人员。
- **核心功能**：`GET /api/team/load` 按真实提交人聚合（user_id 为空时用 user_name 兜底，同人多条日志合并卡点/待审）；按负载指数降序；未提交名单基于历史真实提交人基线。
- **实现状态**：✅ 已实现（`TeamLoadPage.jsx`、`routers/team.js` `/load`）
- **⚠️ 公式口径注意**：README 声明「负载指数 = 阻塞×2 + 待审×1 + 未提交×3」，但**代码实际为 `load = 阻塞数×2 + 待审数×1`（未提交不计入个人指数，仅 summary 单列 notSubmitted 计数）**，且代码过载阈值 `load >= 4` 而 README 档位写「偏高 4–5 / 过载 ≥6」。详见第 8 节，建议按代码统一口径。

### 3.10 日报 / 周报（Reports）
- **描述**：每日基于邮件/待办/日志生成日报；每周基于日报汇总生成周报，全部持久化于本地 SQLite，可回溯。
- **核心功能**：
  - 日报页 `/daily`（`DailyReportPage.jsx`）：真实钉钉日报数据源（`GET /api/reports/dingtalk` + `/dingtalk/dates`，结构化 contents 分区 + 部门筛选）；AI/手动生成 `POST /api/reports/daily/generate`（统计待处理邮件、待办、团队阻塞、需主管审核项 + AI 叙述）；编辑小结 `PUT /api/reports/daily`（合并更新 content_json）；按日期回溯（前一天/后一天）。
  - 周报页 `/weekly`：基于日报汇总生成 `POST /api/reports/weekly/generate`，`week_start` 唯一索引 + `ON CONFLICT` 覆盖生成；按周回溯。
- **实现状态**：✅ 已实现（`routers/reports.js`、`WeeklyReportPage.jsx`、`DailyReportPage.jsx`；`daily_reports` / `weekly_reports` 表）

### 3.11 系统 / 接入（System）
- **描述**：OAuth 连接管理、AI 密钥配置与状态。
- **核心功能**：`GET /api/system` 返回 configured / useDemoData / aiProvider / publicBaseUrl；Outlook / 钉钉连接入口（含设备码通道）；同步状态查看（lastSyncAt / lastError / 各类计数）。
- **Prompt 管理**：所有 AI 提示词集中在 `server/prompts/` 目录，按功能模块管理（email-classifier / report-analyzer / weekly-summary / review-summarizer / daily-suggestion / draft-reply），由 `prompts/index.mjs` 统一导出。
- **实现状态**：✅ 已实现（`routers/system.js`、`SystemPage.jsx`、`sync_state` 表）

## 6. 接入与部署

### 6.1 开发运行
```bash
npm install
cp .env.example .env      # 按需填写 Outlook / 钉钉 / AI 密钥
npm run dev               # 前端 http://127.0.0.1:5174 + API http://127.0.0.1:8787
```
未配置外部服务时自动注入合成演示数据，界面可完整跑通。

### 6.2 接入真实数据
1. Azure Entra 注册应用（**多租户公共客户端**，权限 `Mail.Read` + `offline_access`），回调 **`http://127.0.0.1:5174/api/outlook/oauth/callback`**（经 Vite 代理转发至后端 8787；后端另提供设备码通道，浏览器无法回跳时可用）。
2. 钉钉开发者后台建企业内部应用（日志 / 日程 / 通讯录权限），回调 `http://127.0.0.1:5174/oauth/dingtalk/callback`；日历另需配置 `DINGTALK_MANAGER_USER_ID`。
3. `.env` 填 `OUTLOOK_ENTRA_CLIENT_ID`、`OUTLOOK_TOKEN_ENCRYPTION_KEY`（32 字节 base64）、`DINGTALK_CLIENT_ID/SECRET`、`DEEPSEEK_API_KEY` 等。
4. 重启，在「系统 / 接入」页完成 OAuth 授权（Outlook 亦可走设备码）。

## 8. 文档与代码不一致（建议修订）

复核（2026-08-17）发现的 README 与代码不符处，供校准：

1. **团队负载公式与阈值**：README 声明「负载指数 = 阻塞×2 + 待审×1 + 未提交×3」、档位「正常 0–3 / 偏高 4–5 / 过载 ≥6」；**代码实际为 `load = 阻塞×2 + 待审×1`（未提交不计入个人指数，仅 summary 单列 notSubmitted）**，且过载阈值 `load >= 4`。建议以代码为准修订 README，或在代码中把「未提交×3」补进指数。
2. **团队负载数据来源**：README 称由 `dingtalk_members`（非管理层）聚合，**代码 `/api/team/load` 实际按「历史真实提交人基线 `getRosterBaseline()`」聚合**（dingtalk_members 仅供 `/members` 接口），README 描述过时。
3. **令牌存储位置**：README 称「OAuth 令牌保存在本地 SQLite（`sync_state` 表）」——**Outlook 令牌实际 AES-256-GCM 加密存于 `.local/outlook/state.enc.json`**，`sync_state` 仅存钉钉令牌与同步状态。README 安全说明需修正。
4. **页面地图写表**：README 表格中邮件页「主要写表 `email_flags`（人工覆盖分类）」——**代码中无 `email_flags` 表**；人工覆盖写回 Outlook 本地状态文件（`state.enc.json`）并镜像到 `emails` 表。
5. **规模数字**：README 数据流图写「React 11 页面 / 13 张表」——现为 **13 页面 / 15 张表**（新增 `Overview2Page`、`email_drafts`、`report_templates`）。
6. **OAuth 回调路径**：README 接入说明中 Outlook 回调为 `http://127.0.0.1:5174/api/outlook/oauth/callback`（已正确），但早期 PRD 记录的 `/oauth/outlook/callback` 已废弃——`/oauth/outlook` 现在只是重定向到前端邮件页的入口。

## 9. 已知缺口 / 后续可增强（建议）

- 真实数据依赖手动 OAuth；Outlook 已有 15 分钟自动同步调度器，但钉钉日志/日程同步仍以页面触发为主（日历带 30 分钟 TTL 缓存），缺少统一的定时调度说明与全量任务编排。
- 项目时间线阶段为「手动录入」，未与研发系统（如 TAPD / GitHub）打通。
- 团队负载公式口径待统一（见第 8 节第 1 条）。
- AI 适配层虽可插拔，但切换非 DeepSeek 模型时，邮件分类强依赖 `response_format: json_object`（OpenAI 兼容）；Claude 走正则兜底，Ollama 依赖 `format: json`，边界场景可再增强。
- 自动化测试覆盖面有限（目前仅 `outlook-draft.test.mjs`），日报/周报生成、钉钉归一化等可补单测。
- 所有同步按钮已展示同步状态/错误信息（Outlook 侧齐全）；钉钉侧 `syncError` 已透出，可继续统一「最近一次同步时间」展示样式。
