## 1. 产品概述

| 项 | 内容 |
|---|---|
| 产品名 | 团队每日工作台（Team Daily Workbench） |
| 定位 | 面向**团队主管**的本地优先（Local-First）Web / 桌面工作台 |
| 核心价值 | 把 Outlook 邮件、钉钉日志与日程聚合到一处，用 AI 做分类与分析，配套每日/周报、待办、复盘、日历、项目时间线 |
| 形态 | 浏览器可访问 + 可打包为桌面 `.exe` / `.dmg`；单机本地优先，数据存本地 SQLite |
| 目标用户 | 同时管理多个项目的团队主管（关注需求评审、设计、开发、测试、上线等跨项目时间线） |

**一句话**：让主管每天打开一个面板，就能看完邮件待办、团队卡点、会议、日志、复盘与项目进度，并由 AI 自动产出日报/周报。

---

## 2. 用户角色

- **团队主管（主用户）**：使用全部功能，查看团队日志/负载、授权接入 Outlook 与钉钉、审阅 AI 产出。
- **团队成员（被管理对象）**：通过钉钉日志/日程被拉取数据，其「已提交/未提交」状态在主界面呈现；主管侧可查看与分析，但成员不直接操作本系统。

## 3. 功能需求（按模块）

> 状态图例：✅ 已实现（代码已落地）｜🔌 需配置（框架已实现，填密钥+OAuth 后用真实数据）｜📝 规划中

### 3.1 概览面板（Overview）
- **描述**：默认首页，一打开即看到当日全局视图。
- **核心功能**：聚合展示当日「待处理邮件、会议、团队卡点、未提交日志」。
- **实现状态**：✅ 已实现（`OverviewPage.jsx`，聚合各模块数据）
- **数据来源**：emails / calendars / dingtalk_reports / todos 表

### 3.2 邮件处理（Outlook AI 分类）
- **描述**：拉取 Outlook 邮件，AI 标记为「需处理 / 无需处理」，可手动覆盖。
- **核心功能**：
  - OAuth 接入 Outlook（`Mail.Read` + `offline_access`）
  - AI 分类标记 + 人工覆盖
  - 未配置时注入**合成演示数据**
- **实现状态**：✅ 已实现框架 / 🔌 真实数据需配置（`server/outlook.mjs`、`routers/emails.js`、`EmailsPage.jsx`、`emails` 表）
- **接口**：`GET /api/emails`、`/oauth/outlook`、`/oauth/outlook/callback`

### 3.3 团队日志（钉钉）
- **描述**：拉取钉钉成员日志，AI 提炼阻塞点与待审核要点，区分已提交/未提交，支持历史日期查看。
- **核心功能**：
  - 钉钉 OAuth 接入（日志/日程/通讯录权限）
  - 成员列表与日志提交状态（`dingtalk_members` / `dingtalk_reports`）
  - AI 提炼阻塞点
  - 历史日期回看
- **实现状态**：✅ 已实现框架 / 🔌 真实数据需配置（`server/dingtalk.mjs`、`routers/team.js`、`TeamLogsPage.jsx`）
- **接口**：`GET /api/team`、`/oauth/dingtalk`、`/oauth/dingtalk/callback`

### 3.4 日历 / 日详情
- **描述**：月视图日历，点击任意一天聚合当日邮件、待办、会议、日志与复盘。
- **核心功能**：月视图导航；日详情聚合多源信息。
- **实现状态**：✅ 已实现（`routers/calendar.js`、`CalendarPage.jsx`、`calendars` 表）

### 3.5 今日待办（Todos）
- **描述**：手动添加个人任务，支持状态 / 优先级 / 截止日期。
- **核心功能**：增删改查；状态、优先级、截止日期字段。
- **实现状态**：✅ 已实现（`routers/todos.js`、`TodosPage.jsx`、`todos` 表）

### 3.6 今日复盘（Review）
- **描述**：记录「所做事、所学、所错、状态」，形成成长复盘。
- **核心功能**：每日复盘条目录入与查看。
- **实现状态**：✅ 已实现（`routers/review.js`、`ReviewPage.jsx`、`daily_reviews` 表）

### 3.7 AI 热点（AiHot）
- **描述**：集成公开 AI HOT 接口，多源信源，今日必看 / 可浏览分层。
- **核心功能**：拉取并缓存热点；分层展示。
- **实现状态**：✅ 已实现（`routers/aihot.js`、`AiHotPage.jsx`、`aihot.mjs`、`ai_hot_cache` 表）
- **说明**：使用公开热点接口，非邮件/钉钉类需授权数据源。

### 3.8 项目时间线（Projects / Roadmap）
- **描述**：手动录入项目「需求评审 → 产品设计 → 开发 → 测试 → 上线」阶段，渲染为 roadmap。
- **核心功能**：项目 + 阶段录入；时间线可视化。
- **实现状态**：✅ 已实现（`routers/projects.js`、`ProjectsPage.jsx`、`projects` / `project_phases` 表）
- **说明**：阶段为手动录入，非自动从研发系统同步。

### 3.9 团队负载（TeamLoad）✅ 已实现，正式定义见 README「团队负载定义」
- **描述**：团队负载视图（人员任务/负载概览）。
- **实现状态**：✅ 已实现（`TeamLoadPage.jsx`，对应页面存在，但 `README.md` 功能列表与路由层未明确说明其完整范围；详见第 8 节「文档与代码不一致」）
- **关联**：由 `dingtalk_members`（非管理层）与 `dingtalk_reports`（`report_date=当日`）聚合，经 `GET /api/team/load` 计算负载指数。

### 3.10 日报 / 周报（Reports）
- **描述**：每日基于邮件/待办/日志生成日报；每周基于日报汇总生成周报，全部持久化于本地 SQLite，可回溯。
- **核心功能**：
  - 日报自动生成（`daily_reports` 表）
  - 周报基于日报汇总（`weekly_reports` 表）
  - 历史回溯
- **实现状态**：✅ 已实现（`routers/reports.js`、`WeeklyReportPage.jsx`；`daily_reports` / `weekly_reports` 表）
- **说明**：日报现为独立页 `/daily`（`DailyReportPage.jsx`），支持按日期回溯与编辑小结；周报页 `/weekly` 保留周维度汇总。

### 3.11 系统 / 接入（System）
- **描述**：OAuth 连接管理、配置与状态。
- **核心功能**：Outlook / 钉钉连接入口；AI 密钥配置；同步状态查看。
- **实现状态**：✅ 已实现（`routers/system.js`、`SystemPage.jsx`、`sync_state` 表）

## 5. 数据模型概览

数据库 `better-sqlite3`，主表（依据 `server/db.mjs`）：

- `emails` — 邮件及 AI 分类标记
- `dingtalk_members` — 钉钉成员
- `dingtalk_reports` — 钉钉日志/报告（已提交状态）
- `calendars` — 日历/会议
- `todos` — 今日待办
- `daily_reviews` — 每日复盘
- `daily_reports` — 日报
- `weekly_reports` — 周报
- `projects` / `project_phases` — 项目与时间线阶段
- `ai_hot_cache` — AI 热点缓存
- `sync_state` — OAuth/同步状态
- `schema_migrations` — 迁移记录

## 6. 接入与部署

### 6.1 开发运行
```bash
npm install
cp .env.example .env      # 填 Outlook / 钉钉 / AI 密钥
npm run dev               # 前端 http://127.0.0.1:5174 + API http://127.0.0.1:8787
```
未配置外部服务时自动注入合成演示数据，界面可完整跑通。

### 6.2 接入真实数据
1. Azure Entra 注册应用（权限 `Mail.Read` + `offline_access`），回调 `http://127.0.0.1:5174/oauth/outlook/callback`
2. 钉钉开发者后台建企业内部应用（日志/日程/通讯录），回调 `http://127.0.0.1:5174/oauth/dingtalk/callback`
3. `.env` 填 `OUTLOOK_ENTRA_CLIENT_ID`、`DINGTALK_CLIENT_ID/SECRET`、`DEEPSEEK_API_KEY`
4. 重启，在「系统 / 接入」页完成 OAuth 授权

### 6.3 桌面打包
```bash
npm run electron:build   # 输出 release/ 安装包
```
