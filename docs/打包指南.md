# 团队每日工作台 — Windows 打包指南

把项目打包成 `团队每日工作台 Setup 0.1.0.exe`（NSIS 安装包），领导双击即可安装使用。

---

## 一、最简单：一键打包（推荐）

在项目根目录双击 **`build-exe.cmd`**，或在终端执行：

```cmd
build-exe.cmd
```

脚本会自动完成：释放端口 → 重编译原生模块 → 前端构建 → 打包 → 还原依赖。看到「打包完成」即可，产物在 `release\` 目录。

> 前提：已 `npm install` 过依赖。普通 Windows 终端（cmd / PowerShell）直接跑即可。

---

## 二、手动分步（想了解原理或脚本出问题时）

打开终端，进入项目根目录，依次执行：

```bash
# 0. 如果本地 dev 服务在跑（8787/5174 端口），先停掉，否则会锁住原生模块导致打包失败
#    （任务管理器结束 node 进程，或停掉 npm run dev）

# 1. 构建前端（生成 dist/client）
npm run build

# 2. 把 better-sqlite3 重编译成 Electron 能用的版本
npx @electron/rebuild -f -w better-sqlite3

# 3. 打包（--config.npmRebuild=false 表示跳过它自带的重复编译，因为上一步已做）
npx electron-builder --config.npmRebuild=false

# 4. 【重要】打包后把 better-sqlite3 还原回 Node 版本，否则本地 npm run dev 会报错
npm rebuild better-sqlite3
```

## 三、产物说明（打包完成后 `release\` 目录）

| 文件 | 说明 |
|---|---|
| `团队每日工作台 Setup 0.1.0.exe` | **安装包（发这个给领导）**，双击安装，有开始菜单快捷方式 |
| `win-unpacked\团队每日工作台.exe` | 解包版，免安装直接运行（用于测试） |
| `团队每日工作台-0.1.0-win-x64.zip` | 免安装 zip 版（安装包出问题时作兜底，解压即用） |

- **安装无需管理员权限**（装到当前用户目录）。
- **未做代码签名**，Windows 可能弹「已保护你的电脑 / 未知发布者」→ 点「更多信息」→「仍要运行」即可。

---

## 四、打包后必须验证一步（防白屏）

安装或解包运行后，如果**窗口白屏**，按 `Ctrl+Shift+I` 打开开发者工具看 Console 报错，或检查：

```bash
# 应用打开状态下，另开终端执行，应返回 {"configured":{...}} 的 JSON
curl http://127.0.0.1:8787/api/system
```

- 返回 JSON → 后端正常，白屏是前端问题。
- 连接失败 → 后端没起来（8787 被占用，或 `electron/main.mjs` 的 `isProd` 判断被改回去了）。

> 历史教训：主进程判断「是否打包环境」必须用 `app.isPackaged`，**不能**用 `process.env.NODE_ENV === "production"`（打包后该变量为空，会导致后端不启动 → 白屏）。此问题已修复，勿改回。

## 五、常见问题（打包过程报错）

| 报错 | 原因 | 解决 |
|---|---|---|
| `EPERM: ... unlink better_sqlite3.node` | 8787/5174 的 dev 服务还开着，锁住了原生模块 | 停掉 dev 服务再打包（脚本第 1 步会自动做） |
| `gyp failed` / `SAFE_DELETE_FAIL_CLOSED` | 在 WorkBuddy / AI 助手的终端里跑，被它的「安全删除」拦截 | 换**普通 Windows 终端**跑 `build-exe.cmd`；或用下面的「干净环境」命令 |
| 安装后双击提示 `Installer integrity check has failed` | 杀软扫描未签名大 exe 时改动了文件（偶发） | 重新打包一次；或改用 zip 免安装版 |
| 安装后白屏 | 见第四节 | 检查 8787 是否起来、`isProd` 是否用 `app.isPackaged` |

### 在 WorkBuddy / AI 助手的终端里手动打包（干净环境）

如果一定要在带 shim 的终端跑，给命令加上环境清理前缀：

```bash
env -u NODE_OPTIONS -u PYTHONPATH -u BASH_ENV \
    -u CODEBUDDY_SAFE_DELETE_BULK_GUARD -u CODEBUDDY_SAFE_DELETE_BIN_DIR \
    -u CODEBUDDY_SAFE_DELETE_REPORT_PATH \
    npx electron-builder --config.npmRebuild=false
```

## 六、首次部署前置（只做一次，领导用之前）

应用打包后走 **8787** 端口，OAuth 回调地址和开发的 5174 不同。需在两个开发者后台**各加一条**重定向 URI（**旧的 5174 保留别删**，开发还要用）：

1. **Azure Entra**（Outlook 应用 `f90f8c84-30f8-4190-8217-a6d2745446ac`）
   → 身份验证 → 平台「Mobile and desktop applications」→ 新增：
   `http://127.0.0.1:8787/api/outlook/oauth/callback`
2. **钉钉开放平台**（企业内部应用 `ding1187z82vuda5dxg3`）
   → 登录与重定向 → 新增：
   `http://127.0.0.1:8787/oauth/dingtalk/callback`
